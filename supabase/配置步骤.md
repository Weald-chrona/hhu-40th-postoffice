# 四十号邮局 · Supabase 配置步骤

从零到「管理后台能用」，一共七步，大概 20 分钟。
中途只有第 2 步要等（建项目要几十秒），其余都是点几下。

配置好之后会多出三样东西：

- 所有访客看到的是**同一面**祝福墙（现在是各人浏览器各存各的）
- 违规的信可以**真的下架**（不是在自己电脑上假装删掉）
- 屏蔽词可以在后台加，**不用改代码重发**

---

## 一、注册账号

打开 https://supabase.com ，右上角 `Start your project`。

用 GitHub 账号登录最快，没有 GitHub 就用邮箱注册。
不用填信用卡，免费额度对比赛项目绰绰有余（500MB 数据库、5 万月活）。

---

## 二、建项目

点 `New project`，填四项：

| 填什么 | 填成什么 |
|---|---|
| Organization | 默认那个就行 |
| Name | `hhu-40th-postoffice` |
| Database Password | 点 `Generate a password` 生成，**复制存到记事本** |
| Region | 选 `Southeast Asia (Singapore)`，离国内最近 |

> 那个数据库密码平时用不到（我们是拿前端 key 连的），但丢了要重置，还是存一下。

点 `Create new project`，等 1~2 分钟，等它变成绿色的 `Active`。

---

## 三、建表

左侧栏点 `SQL Editor` → `New query`。

把仓库里 `supabase/schema.sql` 的**全部内容**粘进去，点右下角 `Run`（或按 Ctrl+Enter）。

看到 `Success. No rows returned` 就是成了。这一步会建好：

- `letters` —— 信件表，多了个 `status` 字段（`ok` 正常 / `hidden` 已下架）
- `words` —— 屏蔽词库，已经灌了 40 多个常用词
- `admins` —— 管理员名单
- 一堆 RLS 策略 —— 决定「谁能看什么、谁能改什么」

> 这个脚本可以重复跑。以后改了策略，再跑一次就行，不会清掉已有信件。

---

## 四、建管理员账号

左侧 `Authentication` → `Users` → 右边 `Add user` → `Create new user`。

- Email：填你自己的邮箱，比如 `1203092219@qq.com`
- Password：自己设一个，记牢
- **勾上 `Auto Confirm User`**（不勾的话登录会提示邮箱未验证）

点 `Create user`。列表里出现这个邮箱就对了。

---

## 五、把这个邮箱登记成管理员

回 `SQL Editor`，新开一个 query，把邮箱换成你刚才填的，跑：

```sql
insert into public.admins (email, note)
values ('1203092219@qq.com', 'LLL')
on conflict (email) do nothing;
```

> 这一步不能省。登录成功 ≠ 有权限 —— 权限是这张表说了算。
> 以后要加人（比如让 HYY 也能管），就再插一行；要撤权就删掉那一行，立刻生效。

跑完可以验证一下：

```sql
select * from public.admins;
```

---

## 六、把 key 填进代码

左侧最下面 `Project Settings`（齿轮图标）→ `API`（新版可能在 `API Keys`）。

要抄两个值：

1. **Project URL** —— 形如 `https://abcdefgh.supabase.co`
2. **anon public key** —— 很长一串，以 `eyJ` 开头
   （新版界面可能叫 `Publishable key`，一样能用的那个是 public / anon 那个）

打开 `js/config.js`，填进去：

```js
window.PO_CONFIG = {
  supabaseUrl: 'https://abcdefgh.supabase.co',
  supabaseKey: 'eyJhbGciOiJIUzI1NiIsInR5cCI6...',

  pageSize: 30,
  maxLength: 500
};
```

保存，刷新网页。邮局左下角那行小字会从「本地演示模式」变成「已连接云端数据库」。

> ⚠️ **能公开的只有 anon key**。旁边那个 `service_role` / `Secret key` 千万别写进前端代码，
> 那个等于数据库的万能钥匙，谁拿到谁都能删库。

---

## 七、打开后台

浏览器访问 `admin.html`（本地就是 `http://localhost:8125/admin.html`）。

用第四步建的邮箱密码登录。进去能看到两个标签页：

**信件审核**
- 按信箱、状态筛选，搜署名或内容
- 「下架」= 从所有人的页面上消失，但数据还在，随时能「恢复展示」
- 「删除」= 真删，删主信会连带删掉它下面的回复，不能撤销

**屏蔽词库**
- 加词、删词，访客刷新页面后生效
- 删掉的词会真的不拦了（前端不是把代码里那份当唯一标准）

---

## 八、把自助注册关掉（建议）

`Authentication` → `Providers` → `Email` → 把 `Enable sign ups` 关掉。

不关的话别人也能注册账号。虽然进不了后台（`admins` 表里没他），但少一个口子总是好的。

---

## 几个坑，提前说

**1. 国内访问可能慢**

`*.supabase.co` 在国内时快时慢，偶尔打不开。答辩前**一定要在会场网络下试一次**。
真打不开的话有三个退路：

- 手机开热点给评委看（用你自己的网络）
- 提前录一段操作视频兜底
- 换腾讯云开发的 CloudBase（代码里的 `store` 层是分开的，改一处就行）

代码本身有降级：CDN 拉不到 supabase-js 时会自动退回本地演示模式，页面不会白屏。

**2. 之前本地写的信不会自动过去**

现在 localStorage 里那几百封（包括你测试写的 `sb学校`）只存在你这台电脑上。
接上云库以后是个空的新库，等于从零开始。

如果那些测试数据你不需要了，这是好事——干净的库更适合答辩。
如果想把某些内容搬过去，跟我说，我写个脚本导出。

**3. 第一次登录进不去**

按这个顺序查：

| 看到什么 | 什么原因 |
|---|---|
| 「还没配数据库」 | `js/config.js` 里的两个 key 还是空的 |
| 「Supabase SDK 没加载出来」 | CDN 被拦了，换网络或者刷新 |
| 「这个账号不在管理员名单里」 | 第五步没跑，或者邮箱拼错了 |
| 「数据库拒绝了这次操作」 | `schema.sql` 没跑全，或者 RLS 策略是老版本的 |

**4. 后台页面别外链**

`admin.html` 有了登录保护，但没必要在导航里放链接。
评委问起来可以说「管理端单独一个页面，用 Supabase Auth 登录，数据权限由数据库的 RLS 兜底」——
这比「前端加个密码框」经得起问。
